# Web UI internationalization (i18n)

The web UI ships in **English (`en`, source language)** and **Simplified Chinese (`zh-CN`)**. Every user-visible string goes through [i18next](https://www.i18next.com/) / [react-i18next](https://react.i18next.com/). New UI code is expected to be multilingual from the first commit; lint, TypeScript and the catalog parity test enforce it.

## How the language is chosen

| Step | Source |
|---|---|
| 1 | Explicit choice stored in `localStorage["language"]` (`en` / `zh-CN`) |
| 2 | Otherwise (`system`): first supported entry of `navigator.languages`; any `zh*` tag maps to `zh-CN` |
| 3 | Fallback: `en` |

Users switch in the sidebar user menu (**Language** submenu) or on the login page (top-right select). Choosing **System** removes the stored value and follows browser language changes live (`languagechange`). A choice made in one tab applies to all open tabs (`storage` event); rapid switching settles on the last choice. `<html lang>` always mirrors the active language. If a language chunk fails to load, keys fall back to English.

`main.tsx` waits for `i18nReady` before the first render, so a Chinese UI never flashes English. English is bundled; other languages are code-split per namespace (`import.meta.glob`) and loaded before they become active.

## Layout

```
src/i18n/
├── index.ts          # i18next init, preference store, setLanguagePreference, translateRuntimeKey
├── languages.ts      # SUPPORTED_LANGUAGES, detection, normalisation, persistence
├── resources.ts      # namespace registry (English imports = type source), lazy loaders
├── format.ts         # formatLocalizedDate, getDateFnsLocale, getIntlLocale
├── i18next.d.ts      # typed keys: t('ns:missing') is a compile error
└── locales/<lng>/<namespace>.json
src/hooks/use-language.ts                 # { language, preference, setPreference }
src/components/shared/language-switcher.tsx  # LanguageMenuSub, LanguageSelect
```

### Namespaces

One namespace per feature area; keep keys in the namespace of the code that renders them.

| Namespace | Scope |
|---|---|
| `common` | Generic actions (`actions.save`), statuses, field names, language names, date patterns (`formats.*`) |
| `ui` | `components/ui`, small shared components, generic hooks |
| `layout` | App shell, sidebar, breadcrumbs, route/document titles |
| `auth` | Login, OAuth result, password change |
| `dashboard` | Dashboard pages and widgets |
| `flows` / `flowDetails` | Flow list/form/pages / flow detail tabs (messages, tasks, agents, tools, vector stores, screenshots, terminal) |
| `fileManager` | Shared file manager and flow files |
| `editor` | Markdown editor, terminal component, detail navigation |
| `providers` / `settings` | LLM provider settings / other settings pages (prompts, API tokens, account) |
| `knowledges`, `templates`, `resources` | Respective features and pages |
| `errors` | Generic client-side error texts |
| `apiErrors` | Backend REST error codes (`backend/pkg/server/response/errors.go`), flat keys |

Adding a namespace: create `locales/<lng>/<ns>.json` for **every** language and import the English file in `resources.ts`.

Adding a language: append it to `SUPPORTED_LANGUAGES` and `LANGUAGE_NATIVE_NAMES` (`languages.ts`), add its date-fns/Intl locale in `format.ts`, and create a full `locales/<lng>/` directory.

## Writing translatable code

```tsx
// The first namespace is the default. Every other namespace used with a prefix must be
// listed too: typed keys reject `common:…` unless `common` is in the hook's list.
const { t } = useTranslation(['flows', 'common']);

<Button>{t('common:actions.save')}</Button>
<Input placeholder={t('form.titlePlaceholder')} />
toast.success(t('toasts.deleted', { title: flow.title }));
```

- **Keys are semantic** and camelCase, grouped by component/area: `list.columns.createdAt`, `deleteDialog.title`. Never use the English sentence as the key.
- **Interpolate, never concatenate**: `t('deleted', { title })` with `"Flow \"{{title}}\" deleted"`. Word order differs between languages. For embedded markup use `<Trans>`.
- **Plurals**: `items_one` / `items_other` in `en`, `items_other` in `zh-CN`; always pass `count` and include `{{count}}` in `_other`.
- **No translated strings at module scope.** Module-level arrays/objects (columns, options, zod schemas, route titles) must store keys or be built inside a component/hook (`useMemo(() => createSchema(t), [t])`), otherwise they freeze in the language active at import time. Code outside React (providers' callbacks, `lib/*`) calls `i18n.t('ns:key')` at call time.
- **Dates/numbers**: `formatLocalizedDate(date, 'dateTime')` (patterns live in `common:formats`), `new Intl.NumberFormat(getIntlLocale())`, `getDateFnsLocale()`. Never hard-code `enUS` or `'en-US'`.
- **Backend errors**: `getApiErrorMessage` / `unwrapApiResponse` translate stable error codes via `apiErrors`; the English `msg` is only a fallback. When the backend adds or changes a code in `backend/pkg/server/response/errors.go`, update `apiErrors.json` in every language (English mirrors the backend message verbatim); `TestHttpErrorsHaveWebTranslations` in that Go package fails otherwise. Never branch on English message text.
- **Enum values** coming from the API (statuses, types) stay untranslated in data; map them to labels at render time (`t(\`status.${status}\`)` is not type-checked — prefer an explicit `Record<Status, key>` map).
- **Runtime keys**: `translateRuntimeKey(ns, key)` for keys only known at runtime; it returns `undefined` for unknown keys so callers can fall back.

### Not translated

Logs (`Log.*`, `console.*`), API/GraphQL field values and enums sent to the server, prompts, commands, tool output, user- and agent-generated content, brand/product/model names (Peepie, OpenAI, Docker…), keyboard key names, and generated report/PDF content (`src/lib/report`, a separate product decision). Keep upstream `pentagi` technical identifiers and external service names unchanged.

## Enforcement

- **TypeScript**: `i18next.d.ts` types `t()` against the English files; unknown keys fail `pnpm run build`.
- **ESLint** `i18next/no-literal-string` (`eslint.config.mjs`): JSX text and human-facing props (`title`, `placeholder`, `aria-label`, `label`, `description`, …) must not be string literals. Brand names or symbols that are legitimately literal: add to the rule's `words.exclude`, do not disable the rule inline.
- **Vitest** `src/i18n/locales.test.ts`: every language has every namespace, exactly the English keys (plural forms merged), identical `{{variables}}`, no empty values.
- Unit tests run in English (`vitest.setup.ts` imports `@/i18n`), so they keep asserting English text.

## Chinese style guide and glossary

Simplified Chinese, full-width punctuation (，。：！？（）), one space between Chinese and Latin words/numbers (`API 令牌`, `3 个任务`). Keep product names, protocols and abbreviations in Latin script (Peepie, LLM, API, URL, JSON, Docker, OAuth, GraphQL, Markdown, Token when referring to LLM token usage). Keep placeholders `{{…}}`, `<1>…</1>` and keyboard shortcuts intact.
